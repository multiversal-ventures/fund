Dashboard Architecture — 3 Approaches

How to unify strategy, operations, and data/AI ops into one collaborative surface

A

Evolve the Explorer

Build on the existing Explorer (Alpine.js + DuckDB-WASM). Add new tabs: Layers (upload & overlay scoring models), Analyses (saved queries with Gemini SQL gen), and Workbench (spreadsheet view via SheetJS). The map becomes the hub — toggle layers per person/thesis.

Pros

  • Fastest to ship — extends what works today
  • DuckDB-WASM already loads Parquet + can load uploaded CSV/XLSX
  • Single codebase, same auth, same deploy
  • Partners get the same URL, just a curated view

Cons

  • Explorer is already 11 JS modules — could get unwieldy
  • Alpine.js may strain under complex state (multi-layer map + spreadsheet + SQL)
  • Mobile/presentation mode harder to bolt on
B

New App Shell, Same Engine

Build a new workspace.html with a proper layout: left sidebar (data sources, saved analyses, team layers), center (map or spreadsheet view, switchable), right panel (county detail + Gemini chat). Reuse DuckDB-WASM + Firebase underneath. Explorer stays as the power-user SQL tool.

Pros

  • Clean separation: Workspace for collaboration, Explorer for power queries
  • Purpose-built layout for map + data + conversation
  • Easier to make partner-friendly (hide sidebar, show curated layers)
  • Can adopt a richer UI framework (e.g., Preact or Svelte) without touching Explorer

Cons

  • More upfront work — new page, new JS modules
  • Two apps to maintain (Explorer + Workspace)
  • Need to share DuckDB init logic between them
C

Unified Hub — Replace Index + Explorer

Replace index.html and explorer.html with a single SPA. Top-level navigation: Map (layers + county drill-down), Data (spreadsheet + upload), Analyses (saved queries + Gemini), Present (partner-facing curated view). All team members land on the same app.

Pros

  • One app, one mental model for everyone
  • No context-switching between pages
  • Present mode is built-in, not bolted on
  • Cleanest long-term architecture

Cons

  • Biggest scope — essentially a rewrite
  • Risk of breaking existing workflows during transition
  • Heavier framework likely needed (Svelte/Preact + router)

My recommendation: B — new Workspace alongside Explorer. Gets the collaboration surface right without risking what works today. Explorer becomes the "advanced" tool; Workspace is where the team lives day-to-day.
